# ADR 0001 — Privileged always-on listener in the Alpha AOSP image

- **Status:** Accepted direction (owner policy P-40, 2026-10-12, issue [#424](https://github.com/AlphaCompute/alphaphone/issues/424)). The privilege, permission, IPC and user boundary below is implemented in source. The SELinux boundary is **deferred** (stock `priv_app`, gate G7), the SystemUI op-list source patch is prepared with exact pre/postimage checks, and an [independent Listening chip source candidate](../aosp-listening-chip.md) is prepared. Its SystemUI indicator health lease is implemented in source on both sides with host tests only (not compiled in SystemUI); image/device qualification remains **open**. Image-build, boot and device evidence are still open (see "Acceptance gates").
- **Scope:** the Alpha AOSP image only. The standalone APK and the launcher APK on ordinary Android are unchanged.
- **Supersedes:** the "additive, nonprivileged" admission rule in [decisions.md](../decisions.md) item 5 **for the listener package only**. The ordinary Alpha app stays nonprivileged.
- **Background:** [AOSP always-on listening spec](../market-research/12-aosp-always-on-listening.md) and [technical feasibility](../market-research/10-always-on-tech-feasibility.md). Those are research inputs; this ADR is the decision.

## Decision

Always-on listening is delivered by a separate, small package, `ai.elizaresearch.alphaphone.sense`
(source `android/sense`, image configuration `vendor/eliza/packages/os/android/sense`). It is the only component
that gets microphone privileges beyond an ordinary app.

| Property | Decision |
| --- | --- |
| Package | `ai.elizaresearch.alphaphone.sense`, built by `./gradlew :sense:assembleRelease`. Never a dependency of `:app`; never in the standalone or launcher APK. |
| Partition and privilege | `system_ext` privileged app (`android_app_import`, `privileged: true`, presigned). `android:persistent="true"` and `directBootAware`. |
| Signer | The same release key as the Alpha launcher APK (`ELIZAOS_KEYSTORE_*`). Staging refuses any other signer. The listener's control permission is signature-level. |
| Privileged permissions | Exactly `CAPTURE_AUDIO_HOTWORD` and `START_ACTIVITIES_FROM_BACKGROUND` (privapp allowlist). |
| Never granted | `INTERNET`, `ACCESS_NETWORK_STATE`, `CAPTURE_AUDIO_OUTPUT`, `CAPTURE_MEDIA_OUTPUT`, `CAPTURE_VOICE_COMMUNICATION_OUTPUT`, `BYPASS_CONCURRENT_RECORD_AUDIO_RESTRICTION`, `EXEMPT_FROM_AUDIO_RECORD_RESTRICTIONS`, `RECORD_BACKGROUND_AUDIO`, `MODIFY_AUDIO_ROUTING`, `READ_PHONE_STATE`. No ambient/audio-intelligence role. No power-save exemption. |
| Runtime permission | `RECORD_AUDIO` is **not** pre-granted. The listener requests it only after the user opts in on its consent screen. |
| Users | Installed for the system (primary) user only (`install-in-user-type`). The persistent user-0 process also stops capture whenever user 0 is not the foreground user (`UserManager.isUserForeground`, re-checked on `ACTION_USER_FOREGROUND`/`BACKGROUND`), so it never processes a guest's or secondary user's speech. |
| SELinux | **Deferred, not an exact boundary.** Phase 1 uses the stock `priv_app` domain; no custom policy is added. Network isolation comes from the absent `INTERNET` permission (no inet group, so the kernel refuses inet sockets). A dedicated `alpha_sense_app` coredomain with network `neverallow`s is a tracked hardening step (gate G7), not a precondition: the Eliza tree's custom domain attempt hit about 30 neverallows. |
| IPC | Two exported providers. `ai.elizaresearch.alphaphone.sense.control`, guarded by the signature permission `…sense.permission.LISTENER_CONTROL` and re-checked in `call()`. Methods: `status`, `pause`, `turnOff`. It returns state text only and **cannot** turn listening on or resume it. `ai.elizaresearch.alphaphone.sense.indicator` (`IndicatorLeaseProvider`) is SystemUI's [indicator health lease](../aosp-listening-chip.md#indicator-health-lease): guarded by the platform signature permission `STATUS_BAR_SERVICE` and re-checked in `call()` against a user-0 UID mapping to exactly `com.android.systemui` with the platform signer. Methods: `acquire`, `renew`, `revoke`; it accepts visibility facts only, returns only a lease generation and whether it was accepted, and can only withhold capture. Alpha cannot reach it. Alpha's Settings › Character page shows the listener's status with Pause listening, Turn off listening and Listening settings (`apps/app/src/runtime/always-on-listener.ts`); the listener's notification, Quick Settings tile and its own settings screen offer the same controls. `allow-association` limits associations to Alpha, SystemUI, PermissionController and Settings (whether the consent flow needs more is a G2 check). |
| Invocation | Only while the phone is unlocked (never behind the keyguard), on the wake phrase the listener starts Alpha's existing `AlphaAssistActivity` (ACTION_ASSIST) by explicit component, sharing its identity, with **no extras, data or clip**. Alpha marks the surface `invocation=listener` only when Android reports the listener as caller and the signatures match, ignores the reported caller when the activity is recreated, and reports it once per launch (`takeInvocation` consumes it). A listener origin counts only within 5 s of arriving and only if the keyguard was not showing when it arrived (`AssistInvocation.take`), so an unread one can never open the microphone later. The renderer reads it once the connection has settled (also on a new invocation of the surface already in front) and starts Alpha's voice assistant only while unlocked, visible and not over a dialog or modal, the sign-in sheet or a voice session already in progress (`listenerStartsVoice`); any other assist entry (any app can send ACTION_ASSIST) opens the assistant surface without opening the microphone. |
| Audio handling | 16 kHz mono PCM in RAM only. Local energy VAD and turn segmentation (`SpeechGate`), then on-device recognition with the same llama.cpp engine as Alpha (`libelizainference` through the shared paradee-voice library: `VoiceAssets.install`, then `NativeAsr` on the voice bundle's ASR slot), then a wake-phrase check. Frames, utterances and transcripts are zeroed/dropped after use. Nothing is written to storage; nothing can leave the device from this package. Silero VAD is not used here: the shared paradee-voice JNI the listener packages exports no VAD entry points (Alpha's Silero VAD runs through the embedding host's `ElizaVoiceNative`, which this APK does not carry); adding it is upstream paradee-voice work. After the wake phrase, the turn, its transcription and the spoken reply run in Alpha's voice assistant on the same on-device engine (VAD endpointing, streaming ASR and Paradee TTS through the resident agent's local route); the listener releases the microphone as soon as Alpha records. |
| Capture source | `AUDIO_SOURCE_HOTWORD` (with `CAPTURE_AUDIO_HOTWORD`), which yields to every other client. In addition the listener releases the microphone whenever any other recording is active, pauses while the phone rings and for calls (audio mode) and pauses while its own capture is silenced (microphone privacy toggle). Wake detection is suppressed while any speech-capable playback is active (media, which includes Alpha's WebView voice, assistant, navigation, games, calls, unknown usages). |
| Indicator | The listener's own ongoing foreground-service notification (DEFAULT-importance silent channel, public on the lock screen, status only) with Pause and Turn off usable without unlock and Resume requiring unlock. Listening never runs without it: consent needs `POST_NOTIFICATIONS` as well as `RECORD_AUDIO`, the policy stays in `NOTIFICATIONS_REQUIRED` while the permission, the app's notifications or the channel are denied, blocked, lowered to silent or minimised, or hidden from the lock screen, or while the device-wide lock-screen notification setting is off, and dismissing the notification pauses listening. Android sends no broadcast for a lowered or hidden channel, so while the microphone is held the service re-checks the indicator at least every 15 s (`ListenerPolicy.INDICATOR_RECHECK_MS`), observes the lock-screen setting, and drops any utterance recognised while the indicator is hidden. The image sets `ro.hotword.detection_service_required=true` so HOTWORD capture is attributed to the `RECORD_AUDIO` op, and overlays all six indicator-exempt roles (`config_system{AmbientAudio,Ui,Audio,Notification,Text,Visual}Intelligence`) to empty; staging refuses an overlay that leaves one set or names an Alpha package. `verify-aosp-listener.mjs` refuses an image where any of those roles has a holder or `privacy/camera_mic_icons_enabled` is `false` (AOSP default true; there is no flag-push service on the image). **Partial source work:** the [exact SystemUI patch and development procedure](../aosp-listener-systemui.md) adds `OP_RECORD_AUDIO_HOTWORD`/`OP_RECORD_AUDIO_SANDBOXED` to both indicator op lists and microphone type mapping. It has not been compiled or booted. The [independent Listening chip source candidate](../aosp-listening-chip.md) implements platform recording observation and Pause without widening Alpha's provider access, and holds the listener's indicator health lease: the listener captures only with a fresh SystemUI acknowledgement of a visible Listening surface, and unexplained losses (SystemUI death, lease expiry (3 s) without a report, revoke, an unattributed recording, a hidden or detached chip without a reason, an unknown display state while the screen is on) stop capture and latch `STOPPED_INDICATOR_LOST` until the user resumes. SystemUI reports lock-screen/AOD (keyguard chip), unlocked status bar, expanded shade (only via the verified listener notification), immersive status-bar hiding and the display state. With the screen off, listening continues while AOD shows the chip. A hidden indicator that SystemUI explains pauses capture (microphone released) and resumes on the next visible acknowledgement: display off or AOD not showing it (`PAUSED_DISPLAY_OFF`, asking for Always-on display), an app fullscreen (`PAUSED_FULLSCREEN`), the shade open without the listening notification (`PAUSED_SHADE`), and a report within 1 s of a lock/unlock or screen-state change (`PAUSED_TRANSITION`). Without the chip patch the listener never captures (`INDICATOR_UNAVAILABLE`), so listener staging includes the chip in every product, production included (`listener/evidence.json`). The lease is source plus host tests only; SystemUI compilation and image/device checks remain open (spec §3.4 rule 5). Until G3 passes, the consent text says the system indicator is *expected* to show, not that it does. |

### Hardware invocation

The overlay sets press-and-hold power to the default assistant (`config_longPressOnPowerBehavior=5`,
user-changeable in Settings) and keeps power + volume up as the power menu
(`config_keyChordPowerVolumeUp=2`) so shutdown, restart and Emergency stay reachable. Emergency SOS
(repeated power presses) and the double-press-power camera gesture are not overridden; staging
refuses an overlay that changes them. The assistant role holder is Alpha (existing provisioning
overlay), so press-and-hold reaches the same `AlphaAssistActivity`. The standalone APK on ordinary
Android uses only permitted entrypoints: the ACTION_ASSIST activity when the user selects Alpha as
assistant, and the in-app microphone.

### Listener states

`OFF → (consent, permission) → WAITING_FOR_UNLOCK → LISTENING ⇄ PAUSED_{USER, CALL, MIC_IN_USE, MIC_UNAVAILABLE}`,
plus `PERMISSION_REQUIRED`, `SPEECH_UNAVAILABLE`, `STOPPED_AFTER_ERRORS`, `INDICATOR_UNAVAILABLE`, `STOPPED_INDICATOR_LOST`, `PAUSED_DISPLAY_OFF`, `PAUSED_FULLSCREEN`, `PAUSED_SHADE` and `PAUSED_TRANSITION`. The rules are in
`ListenerPolicy` (pure Java, tested on the JVM):

- Off by default; consent is versioned (`CONSENT_VERSION`) so a change in what is captured or where it goes requires opting in again. Withdrawal clears the record.
- Before first unlock after boot the listener never captures and says "Listening starts after unlock".
- Revoking `RECORD_AUDIO` stops capture (Android also kills the process); restarts without the permission are not counted as crashes.
- Crash loop: three unclean exits (a capture session left open in the same boot by the same install) within ten minutes stop listening until the user turns it back on. Shutdowns (`ACTION_SHUTDOWN` closes the marker), reboots, OTAs and package updates are not counted. The trip is sticky; ageing out never restarts capture.
- The listener's notification must be visible (`NOTIFICATIONS_REQUIRED` otherwise) and user 0 must be the foreground user (`PAUSED_OTHER_USER` otherwise).
- Timed pauses run on the monotonic clock, so a wall-clock change cannot end them early; a timed pause from an earlier boot lasts until the user resumes.
- Saying "Alpha, stop listening" pauses until resumed.
- Every microphone-holding state needs a fresh SystemUI indicator lease (`INDICATOR_UNAVAILABLE` otherwise). Losing it while the microphone is held latches `STOPPED_INDICATOR_LOST`; only an explicit resume, turn-on or new consent clears it, never a pause or a returning lease. An explained hidden indicator (display off, AOD not showing it, fullscreen app, shade, keyguard/screen transition) is a pause that resumes on a visible acknowledgement, not a loss; an unexplained loss latches, also during such a pause. Lease loss is a clean stop and never counts toward the crash-loop breaker; a fresh lease never overrides the breaker, missing consent or before-first-unlock.

## Consequences

- Alpha (`ai.elizaresearch.alphaphone`) gains no privileged permission. It holds only the listener's signature permission and package visibility for it; on phones without the listener everything reports unavailable.
- The listener APK packages its own copy of the voice engine and bundle: the staged `.eliza/paradee-voice/native` engine and the `assets/paradee-voice/v1` bundle through `:local-speech`, the same bytes as `:app`, checked against `android/voice-host/qualified-voice-host.json` ([fused speech](../fused-speech.md)). No other speech runtime exists. Without the ASR slot pair the listener reports speech unavailable and never listens. Sharing one image-resident model file is an optimisation, not part of this decision.
- Sense is a `presigned`, `preprocessed` privileged import: modern APK signatures must not be rewritten by Soong. Before copying listener files, staging rejects compressed JNI/DEX and unaligned stored entries (16 KiB for JNI, 4 bytes otherwise). It never repairs a signed APK. Preserve the normal signed output; build an unsigned copy of the same variant, run `scripts/prepare-aosp-apk.py`, then sign with the same launcher certificate. Compare all payload entries to the original, and run the pinned Soong presigned checker with `--preprocessed --privileged --uncompress-priv-app-dex` before image integration. Do not use `skip_preprocessed_apk_checks`. Signature, permissions, speech integrity and production qualification remain separate gates.
- Production staging (`npm run aosp:stage -- --production`) requires `--listener-apk` and a reviewed `--listener-descriptor` pinning the listener's `apkSha256` and `certificateSha256`, and refuses a listener APK without `assets/paradee-voice/v1/manifest.json` carrying the ASR slot pair, without an ABI that packages `libelizainference` and `libparadeevoicejni`, or whose packaged engine libraries differ from `android/voice-host/qualified-voice-host.json`.
- The listener has its own qualification record, `android/sense/qualified-listener.json` (`scripts/listener-qualification.mjs`): `qualified: false`, gates G1–G6 open, the 2026-10-12 developer build marked historical (it predates the lease), no emulator, image or device evidence. `scripts/verify-apks.mjs` writes a `listener` section into `apk-manifest.json` with a row per `sense-*.apk` copied next to the Alpha APKs (hash, signer, permissions against the privapp allowlist, no network, voice bundle) and fails on a listener APK that requests network access or unreviewed permissions. Those rows are APK-build evidence and are never distributable while the record is unqualified; bytes never qualify it.

## Acceptance gates (not established by source changes)

| Gate | Evidence needed |
| --- | --- |
| G1 Image build | `vendor/alphaphone` with the staged listener builds; privapp enforcement accepts the allowlist. |
| G2 Boot and grants | `node scripts/verify-aosp-listener.mjs --serial S --user 0` passes on the booted image: system, privileged, persistent, `CAPTURE_AUDIO_HOTWORD` granted, no network permission, Alpha nonprivileged, indicator property set; no listening before consent. |
| G3 Indicator | The system microphone indicator, the Listening chip and the listener notification are visible while listening, on the lock screen and AOD, including with "hide silent notifications" on; killing SystemUI, hiding the chip surface (immersive, shade, occluding windows) and an unattributed recording stop capture within the lease bound and do not resume it; with the screen off, listening continues while AOD shows the chip, and with AOD off it pauses and resumes when the lock screen shows the chip (AOD and HOTWORD may need the open SystemUI op-list patch and Listening chip, spec §3.4 rules 3 and 5). HOTWORD attribution under `ro.hotword.detection_service_required` is checked at the pinned AOSP tag. Pixel `PixelConfigOverlay*` must not re-assign the cleared roles. |
| G4 Hardware invocation | Press-and-hold power opens Alpha's assistant surface; power + volume up opens the power menu; Emergency SOS and double-press camera unchanged — on a physical Pixel 10a. |
| G5 Coexistence | User switch to a guest or secondary user stops capture; ringing, calls, another recording app, Alpha's own voice turn, media playback and Bluetooth routing; the listener pauses and recovers; assistant speech does not re-invoke it (echo). |
| G6 Reliability and power | Stop/pause reliability from notification, tile and lock screen; reboot before unlock; crash-loop behaviour; battery and thermal cost over a multi-hour and a 24-hour listening run. |
| G7 Hardening | Optional custom `alpha_sense_app` SELinux domain and isolated speech process, evaluated after G1–G2. |

APK builds, image staging, an image boot, real integrations and device/user acceptance are separate
gates; none of them proves another.

Persistence failures latch listening off and stop the service. Capturing starts only after the open-session marker saves successfully. A fresh listener process requires explicit opt-in again, even when disk contains older consent, so a failed stop save cannot resurrect capture after restart. The consent screen discloses this restart behavior.
