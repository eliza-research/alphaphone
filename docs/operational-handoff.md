# Operational hand-off index

This page indexes what an operator needs to build, provision, run and support Alpha Phone
(MVP-51). It is an index, not a runbook: each entry links the document or file that owns the
subject. Nothing here is evidence above class S. A linked procedure that has never been run on
the current source says so in its own document, and the gaps named below are open.
`test/operational-handoff-links.test.mjs` checks that every repository path on this page exists.

## Upstream references

- Pinned upstream commit and source paths: [`upstream.lock.json`](../upstream.lock.json); the
  recorded reachability of that commit from elizaOS `develop`:
  [`scripts/ci/upstream-reachability.json`](../scripts/ci/upstream-reachability.json), checked by
  [`scripts/verify-upstream.mjs`](../scripts/verify-upstream.mjs).

- Ownership between this repository and upstream: [architecture](architecture.md). Upstream

## Backup and export

Decided by P-25 (A-19, [decisions](decisions.md#october-12-owner-decisions)): no app-data backup,
import/export or device transfer; a confirmed Reset Alpha data erases Alpha's private data. Data
does not move to a new phone. `scripts/pilot-update.mjs` reads an in-app
integrity export on release units (file HMACs only, no names or contents leave the device);
that is an update check, not a user data export.

## Rollback

Not offered. A lower versionCode cannot replace an install without removing its data, and
`scripts/pilot-update.mjs` refuses it. Alpha Compute holds signing and update authority and the
release owner is accountable for rollback (A-06). The update channel records
`downgradeAllowed: false`, the stock factory image for recovery and a known-good release slot;
the signed-update, interrupted-update, compatible-rollback and stock-recovery drills are all
recorded as not run.
