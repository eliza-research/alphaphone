## Architecture and task boundaries

- The primary agent runs on the Android device. Browser development runs the real agent on this computer through the private local bridge. Cloud and remote pairing remain optional connection paths. Neither Cloud login nor Nitro/KMS admission is required to start the primary local agent.
- Orchestration is local; the current text model is hosted Cerebras. Whisper/Kokoro provide local speech on the browser host; Android has its own packaged native path. Host speech does not prove Android speech quality or device execution.
- A powered-off phone cannot execute its resident agent. The on-device plan proposes durable missed-occurrence/restart/reconnect behavior as a replacement for the former powered-off hosted-loop requirement, but explicitly requires acceptance agreement. That disposition remains open; local recovery is not evidence of powered-off execution. Optional remote execution needs separate qualification; no existing remote deployment is to be shut down as part of this change.
- The browser workstream recorded below skipped Android builds. That historical scope does not waive repository verification: the reviewed integration at `e8d6838f90307d201eb530cbfbc9a0d27f776b09` passes both Android distribution builds. Native source checks may improve implementation, but APK, emulator, full image and physical-device acceptance remain separate evidence categories.
- Notes, Calendar, Reminders, browser/password-provider integration, notifications, voice/text assistance, workflows/digests and supporting settings/files/capture remain in scope. Gmail is retained as an integration gap. Deferred Phone/SMS/Contacts/Wallet entries do not become required merely because the development simulator contains them.
